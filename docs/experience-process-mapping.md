# Скилл «Карта процесса-опыта»

`experience-process-mapping` помогает создавать, обсуждать, проверять
и изменять КПО: от границ процесса и опыта участников до работы
с дорожками, узлами, связями и аннотациями в Социотехе.

## Возможности

- моделирование текущего, целевого и явно смешанного состояния;
- выбор ключевых, опциональных и неконтролируемых точек;
- разделение следования, взаимодействия, ожидания и условных ветвей;
- анализ входов/выходов, каналов, барьеров и средств;
- фасилитация по неполным материалам без выдуманных фактов;
- чтение и изменение КПО через 40 объявленных операций XPM;
- структурный аудит вместе с отдельной методической проверкой;
- передача контекста из КГ и привязка узла к существующей истории КРИ;
- сохранение ID, чужих данных и проверка частично выполненных изменений.

Метод не сводится к CJM, BPMN, бэклогу или КРИ.
Карта одного участника допустима. Разрабатываемая ИТ-система описывается
в аннотациях; отдельная дорожка допустима для внешнего сервиса/API,
который нельзя изменить. Это уточнение авторской методички учтено
вместе со стандартом нотации 1.0.

## Установка

Скопируйте папку
[skills/experience-process-mapping](../skills/experience-process-mapping)
целиком в каталог скиллов своего ИИ-агента.
Для черновика в диалоге подключение не требуется.
Для чтения и изменения проекта нужен MCP Социотеха:
https://sociotech.center/mcp.

Папка самодостаточна; другие скиллы устанавливаются по желанию.

## Примеры запросов

> По интервью составь черновик КПО процесса возврата товара. Покажи текущий
> процесс, взаимодействия, входы/выходы и неизвестное. В Социотех пока не пиши.

> Проверь КПО проекта по этой ссылке: отдельно структуру и смысл.
> Обрати внимание на ложную синхронность и переходы между каналами.
> Ничего не меняй.

> Вставь «Проверку комплектности» между указанными точками КПО.
> Сохрани остальные данные и проверь новые связи.

> Свяжи узел «Приём техники» с существующей рабочей историей КРИ,
> если её содержание соответствует точке. При неоднозначности покажи кандидатов.

## Источники и ограничения

Исходные материалы и результаты поиска полного текста книги описаны в
[справочнике источников](../skills/experience-process-mapping/references/sources.md).
На Яндекс Книгах и Ridero изучены доступные фрагменты; чтение полного
издания не заявляется.

MCP сверён 2026-11-06. Имена операций в справочнике — снимок, а не
постоянный контракт. Перед работой агент обязан сверить runtime.
В текущем снимке не заявлены экспорт КПО, отдельный тип узла `event`,
создание самой XPM-карты и специальная ИИ-генерация КПО.
События при узле поддержаны текстовыми вложениями.

При исходной подготовке скилла пользовательские проекты не изменялись.
Позже, 2026-11-06, на разрешённой пользователем правке проверены операции
и ограничения, перечисленные в дополнении справочника источников.
Контрактная и сценарная проверки не заменяют интеграционную проверку
на специально выделенной тестовой доске.

## Проверка

Выполните `python3 scripts/validate_repository.py`.
Поведенческие случаи находятся в
[eval-сценариях](../tests/experience-process-mapping-evals.md).
При обновлении MCP менять справочник операций, рабочий процесс и сценарии
вместе; не добавлять неподтверждённые возможности по аналогии с КРИ.

В частичном архиве общий `scripts/validate_repository.py` может отсутствовать;
тогда не заявлять его выполненным. Для поставляемого анализатора доступны:

```bash
python skills/experience-process-mapping/scripts/lint_xpm.py /path/to/xpm.json
python -m unittest discover -s tests -p test_xpm_lint.py
```

Анализатор работает без сети и записи. Код 0 не заменяет ручную методическую
проверку; все сигналы `review` нужно рассмотреть. Обновление набора
2026.11.06-r2 не меняет номер авторского стандарта 1.0.
