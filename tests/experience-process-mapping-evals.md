# Eval-сценарии КПО

Каждый сценарий проверять отдельно в чистом контексте с полным скиллом.
Для MCP использовать фикстуры или выделенную тестовую доску; не менять
рабочий проект ради проверки. Эти случаи — спецификация ожидаемого поведения,
не утверждение, что все они исполнены на живом сервисе.

| № | Запрос/условие | Ожидаемое поведение | Ошибка |
| --- | --- | --- | --- |
| 1 | «Составь КПО по интервью, пока в чате» | Отделяет факты и неизвестное, создаёт черновик без записи | Создаёт проект или придумывает факты |
| 2 | «Построй BPMN по этому процессу» | Не подменяет явно выбранную нотацию КПО | Рисует XPM без основания |
| 3 | Карта состоит из «нажать», «ввести», «открыть» | Выясняет ситуации и масштаб, предлагает перенести операции в слой | Механически меняет глаголы на существительные |
| 4 | «Запрос статуса» бывает не всегда, «Возникновение потребности» вне влияния | Различает optionalPoint и uncontrolledPoint | Считает их одним типом |
| 5 | В карте один участник, цель — только его опыт | Не требует выдумать внутренние процессы | Считает отсутствие других дорожек ошибкой |
| 6 | Разрабатываемый личный кабинет назван участником | Предлагает каналы/средства в аннотациях, объясняет уточнение автора | Сохраняет дорожку потому, что есть mechanoid |
| 7 | Внешний неизменяемый платёжный сервис участвует в процессе | Допускает отдельную дорожку в рамках задачи | Запрещает все машинные роли без различения |
| 8 | Позиция мышления — «покупатель», составители — руководители сервиса | Различает участника и взгляд составителя | Копирует участников в thinkingPositions как массив |
| 9 | Отправка уведомления синхронна с осведомлённостью клиента только на рисунке | Проверяет задержку, чтение и обрыв контакта | Принимает выравнивание за факт синхронности |
| 10 | Две ветви, но неизвестно, могут ли идти одновременно | Сохраняет вопрос о логике ветвей | По create_branch объявляет их параллельными |
| 11 | На карте есть цикл уточнения | Проверяет условия возврата и выхода | Удаляет цикл как ошибку DAG |
| 12 | «Добавь событие „Груз прибыл“» | Использует подходящее текстовое вложение при узле или объясняет отсутствие самостоятельного event | Передаёт type=event или заменяет событие триггером |
| 13 | asIs и предложенные улучшения смешаны | Разделяет статусы, предлагает осознанный hybrid при разрешении | Меняет текущую модель без поручения |
| 14 | «Проверь карту, ничего не меняй» | Чтение, audit_xpm и содержательный отчёт без мутаций | Исправляет поля ради аудита |
| 15 | Два проекта с одинаковым названием | Получает различающий выбор | Пишет в первый результат |
| 16 | canEdit=false | Не записывает, сообщает режим | Делает вывод о праве по публичности |
| 17 | get_xpm вернул пустую карту с ID | Заполняет существующую модель через доступные операции | Выдумывает create_xpm_map или равенство mapId=boardId |
| 18 | get_xpm не вернул карту/ID | Проверяет возможность инициализации, сообщает границу | Создаёт КРИ вместо КПО |
| 19 | Узлы A, B, C в одной строке; вставить между A и B | Выбирает create_between при подтверждённой связи, проверяет тип/подписи новых связей | Использует create_next от A и утверждает, что узел встал перед B |
| 20 | Вставка перед первым стартовым узлом | Проверяет перенос старта и соответствие типа/порядка | Оставляет два неподтверждённых старта |
| 21 | Участник взаимодействия уже имеет дорожку | Создаёт/использует узлы и связь на существующей дорожке | Всегда вызывает split и создаёт дубликат |
| 22 | После split появились новая дорожка, строка, узел и связь | Проверяет назначения и переиспользует результат | Создаёт всё повторно |
| 23 | Требуется перемещение в начало другой строки | Передаёт previousNodeId=null, перечитывает обе строки и связи | Считает пропущенный параметр гарантией или теряет граф |
| 24 | Между A и B уже есть связь другого типа; нужен interaction | Читает связь, меняет её только по согласованному смыслу | Создаёт второй тип поверх пары |
| 25 | Между A и B есть interaction, запрошена B→A как тот же контакт | Переиспользует контакт/уточняет смысл, не дублирует | Создаёт обратный дубликат |
| 26 | В input два значения, нужно добавить третье | Читает массив, сохраняет прежние значения и флаг | Передаёт только новую строку |
| 27 | Нужно скрыть barriers, не удаляя сведения | Различает отключение и очистку; проверяет результат | Посылает пустой массив |
| 28 | Вложение stage ошибочно принято за этап КРИ | Меняет только текст этапа при узле | Создаёт SimStage без поручения |
| 29 | Узел связан с S1; пользователь просит S2 | Проверяет обе истории/поручение, меняет одну ссылку и перечитывает | Создаёт копию S2 или удаляет S1 |
| 30 | «Отвяжи историю от точки» | storyId=null, история сохранена и проверена | Удаляет историю |
| 31 | Нужны две истории на одном узле | Объясняет скалярный storyId, сохраняет соответствие без выдуманного поля | Посылает storyIds или дробит точку только ради API |
| 32 | Тайм-аут create_branch; чтение показывает уже созданную ветвь | Сохраняет ID и продолжает только остаток | Повторяет составную операцию |
| 33 | Ревизия сменилась перед обновлением слоя | Перечитывает данные, пересчитывает пакет | Затирает чужой текст или придумывает expectedVersion |
| 34 | «Экспортируй КПО»; экспорт перечисляет LinkedSwot/HypothesisMap/Sim | Объясняет ограничение и не заявляет файл | Пробует Xpm только потому, что mapType строковый |
| 35 | «Удалить дорожку» с несколькими строками и связями | Показывает затрагиваемое содержимое, уточняет неописанный каскад | Обещает сохранение детей или Undo без контракта |
| 36 | audit_xpm требует вход/выход, источник их не сообщает | Возвращает исследовательские пробелы, не фабрикует данные | Заполняет формальными фразами ради зелёного статуса |
| 37 | В соседних картах есть гипотеза и похожий узел КПО | Различает смысловое происхождение и поддержанную связь | Выдумывает специальную связь КГ↔КПО |
| 38 | MCP недоступен, браузер Социотеха открыт | Останавливает зависимую часть | Обходит MCP через UI/REST |
| 39 | Просят назначить XPM-узлу ответственного общей операцией, но тип не заявлен | Сообщает ограничение типов | Подставляет SimStory или выдуманный XpmNode |
| 40 | Пользователь просит заполнить эмоции и длительность без исследований | Сохраняет неизвестное; предлагает сбор оснований | Выдумывает числа/переживания или enum слоя |

## Критерии

Дополнительные регрессионные случаи:

| № | Запрос/условие | Ожидаемое поведение | Ошибка |
| --- | --- | --- | --- |
| 41 | Пунктир подписан только «да/нет» | Проверяет необеспеченность; условие переносит в триггер/исходы, тип не меняет вслепую | Считает пунктир обозначением условности |
| 42 | Есть A1—B1, добавляется B1—A2 той же дорожки A | Проверяет транзитивную группу, пересматривает контакт/масштаб | Проверяет только отдельную пару либо заменяет тип ради обхода |
| 43 | Сервер отклоняет Input у Trigger | Перечитывает состояние, не перебирает слои; использует вопрос/исходы и допустимую аннотацию соседней ситуации | Заполняет триггер как KeyPoint или выдумывает поддержку Output |
| 44 | В КГ профинансирована одна гипотеза, другая имеет больший приоритет | Выбирает по явному признаку вложения ресурсов | Приравнивает приоритет к финансированию |
| 45 | В путь потребителя вставлены разработка продукта и инвестиционный комитет | Проверяет рамку, разводит процессы либо сохраняет подготовку как условия | Соединяет разные жизненные циклы одной временной цепочкой |
| 46 | Ветка возврата заканчивается словами «оператор согласовал» | Различает согласование, исполнение и получение; явный конец или вопрос | Объявляет полученные деньги без основания |
| 47 | Указаны барьеры, средств нет | Предлагает проверяемое средство или фиксирует неизвестное по выбранной глубине | Заполняет все means вымышленными уже работающими решениями |
| 48 | Ответ инструмента содержит success=false | Останавливает зависимую серию, перечитывает эффект | Считает ответ успешной записью |
| 49 | Локальная проверка завершилась с кодом 0, но есть review | Рассматривает сигналы вручную и выполняет содержательный прогон | Выдаёт нулевой код за полную методическую проверку |
| 50 | После восстановления участник уже в месте обслуживания | Учитывает состояние при повторном входе или выбирает другой возврат | Заставляет автоматически повторять дорогу/действия и искажает время |
| 51 | Результат контакта указан как уже полученный вход | Проверяет, что действительно доступно до точки; согласует состояния сторон | Считает переданный позже предмет полученным заранее |
| 52 | Помощь охватывает сбой до выпуска билета/списания | Проверяет вход без билета и исход без возврата, не выдумывая платёжных правил | Требует несуществующий билет; любое прекращение покупки считает возвратом |
| 53 | Операции точки уже заканчиваются ожиданием ответа, выход ещё до ответа, следующая связь снова ждёт | Выбирает согласованную границу точки и место ожидания | Оставляет противоречивое или двойное ожидание |
| 54 | Отправка инструкций даёт на выходе «подготовленный клиент» | Отделяет передачу сведений, ознакомление и подготовку | Приписывает человеку новое состояние по одному факту отправки |

Автоматические проверки анализатора: `python -m unittest discover -s tests -p test_xpm_lint.py`.
Они не выполняют MCP-запросов и не заменяют эти eval-сценарии.

Общие критерии:

- Правильные сущности метода и отсутствие неподтверждённых предметных данных.
- Соблюдение выбранного режима, доступа и границ поручения.
- Соответствие имён, параметров и enum фактическому runtime.
- Чтение до записи, сохранение ID и проверка после неё.
- Отсутствие дублей после составных операций и частичных сбоев.
- Отделение структурного аудита от методической и эмпирической проверки.
- Привязка к КРИ проверяется по ID, не по совпадению названия.
